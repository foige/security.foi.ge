# INT-00001: FOI Security Product Identity

## Summary

Define the product spec for FOI Security — the foundational identity document that every
downstream spec traces to. FOI Security is an open-source cybersecurity guide and toolkit
that makes security decisions for users who don't have time or expertise to make them
themselves. It exists because digital privacy is under active, real-world attack — particularly
in Georgia, but globally — and existing security advice is fragmented, jargon-heavy, and
overwhelming. The product must remain opinionated, accessible, and honest.

## Interview Claims

Claims extracted from the existing site content, about page, terms of service, trainers
guide, pitch materials, and codebase structure.

### Anchors

- [USR-00002] [goal] The product makes security decisions for the user. Not "it depends" — "do this." Choices are offered only when the choice genuinely belongs to the user.

- [USR-00003] [goal] The product protects the user's digital privacy as an extension of their right to private thought. "Your data is an extension of your mind" is the foundational belief.

- [USR-00004] [hard_constraint] The product itself must be privacy-preserving. No tracking cookies, no affiliate links, no ads. Analytics (Plausible) is minimal and anonymous. The password generator runs entirely client-side with SHA-256 integrity verification.

- [USR-00005] [hard_constraint] Everything is open source. The code, guides, policies, and tools are publicly available on GitHub under CC BY-NC-SA 4.0. The project must survive any individual — "democracy tools shouldn't have single points of failure."

- [USR-00006] [hard_constraint] Security recommendations must balance security with usability. The trainers guide explicitly warns against making security hateful — biometrics stay on, comfort matters, the goal is sustainable security, not paranoid security.

- [USR-00007] [goal] The product addresses real-world threat models: device seizure (Cellebrite), state surveillance, SIM swapping, cloud key escrow by vendors (Microsoft, Apple). Not theoretical risks — threats the audience actually faces.

### Negotiable

- [USR-00008] [fact] The current audience is Georgian-speaking. All content is in Georgian. English translation is a stated future goal but not yet implemented.

- [USR-00009] [fact] The product has four pillars: (1) solutions guides (step-by-step instructions), (2) FOI Security Policy (installable system profiles), (3) FOI Password Generator (client-side passphrase generator), (4) FOI CLI Tools (automation scripts for Windows/macOS).

- [USR-00010] [fact] Content follows a consistent structure: Problem (what we're solving) → Risk (what happens if we don't) → Solution (what to do). Each solution page has prerequisites, step-by-step instructions, and video examples.

- [USR-00011] [fact] The product recommends specific tools by name: Bitwarden, Ente Auth, Signal, Mullvad VPN, Google Pixel. Recommendations are singular and opinionated — not comparison lists.

- [USR-00012] [preference] The tone is direct, practical, and treats the user as an intelligent adult who simply lacks domain knowledge. No condescension, no jargon without explanation, no fear-mongering — but no sugar-coating either (Microsoft is explicitly compared to a virus).

- [USR-00013] [preference] The product is free forever. It serves as the trust builder.

- [USR-00014] [fact] The product was created in response to Georgia's "Russian law" and associated restrictions on expression and privacy. It originated from workshop series with activists and civil society, refined through dozens of in-person sessions.

- [USR-00015] [fact] The trainers page establishes FOI Security as a resource for both end-users and security trainers, with explicit guidance on pedagogy: focus on "why" not "how", respect comfort, avoid shaming.

## Research Notes

- Site structure: MkDocs Material site, `mkdocs.yml` at root. Nav has 5 top-level sections: Home, Solutions, FOI Security Policy, Password Generator, About. Guide section commented out.
- Solutions section organized: Basic (passwords, MFA) → OS (Win/Mac/iOS/Android) → Recommendations (messaging, DNS, VPN, antivirus) → Threats (misconceptions, behavior, hardware-keys).
- Password generator: `docs/assets/javascripts/password-generator.js` (452L), CSS (593L), 4 wordlist files (~9000-14000 lines each in Georgian and English), integrity checksums in page template.
- Security policies: Windows uses GPO via PowerShell script (`docs/policies/files/windows/foi_tools.cmd`, 467L), macOS/iOS use `.mobileconfig` profiles. Windows policy alone changes 124+ parameters documented in `docs/policies/windows.md` (1054L).
- CLI tools: `docs/policies/files/windows/foi_tools.cmd` (Windows, 467L), `docs/policies/files/apple/foi_tools.sh` (macOS, 165L). Windows tool handles: policy installation, PIN enforcement, fingerprint timeout. macOS tool handles: FileVault user enforcement.
- Empty file: `docs/fde.md` (0L) — likely planned Full Disk Encryption page.
- `about/trainers.md` is the only page that addresses a secondary audience (trainers vs end-users).
